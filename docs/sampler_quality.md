# Hidden-state sampler quality benchmark

This **offline** experiment measures whether using observed opponent actions
helps infer the holders of the remaining hidden cards. The actual hands are
kept outside `HiddenStateSampler` and the evidence scorer; they are only read
by the final scoring function.

## Run

```powershell
git switch feature/unified-agent-benchmark
git pull origin feature/unified-agent-benchmark
uv run pytest tests/test_sampler_quality.py tests/test_hidden_state_sampler.py tests/test_action_evidence.py
uv run python scripts/evaluate_sampler_quality.py --games 10 --samples 16 --opponents heuristic --output results/sampler_smoke.csv
uv run python scripts/evaluate_sampler_quality.py --games 100 --samples 32 --candidates 4 --opponents heuristic --seed 20261205 --output results/sampler_quality_heuristic.csv
```

To check whether evidence weighting generalizes to less predictable behavior:

```powershell
uv run python scripts/evaluate_sampler_quality.py --games 100 --samples 32 --candidates 4 --opponents random --seed 20261206 --output results/sampler_quality_random.csv
```

The script extracts four player-to-move snapshots per completed game (after 4,
12, 20 and 28 played cards), representing different stages. Every position is
evaluated by the unweighted baseline and the evidence-weighted sampler.
Both produce 32 sampled hands per position by default; weighted sampling
draws 4 candidate hands for each accepted hand (128 proposals in total).

## Metrics

- **Brier score:** average squared probability error across every unseen card
  and each of the three possible opponent holders. **Lower is better.**
- **Log loss:** mean smoothed negative log probability given to the actual
  holder. **Lower is better.** Smoothing makes estimates finite.
- **True-holder probability:** mean probability assigned to the correct holder
  over all unseen cards. **Higher is better.**
- **Seconds:** time needed to generate the sampled determinizations.

The CSV records each position and method, including game, turn, contract,
hidden-card count and metrics. The summary JSON reports the means and paired
differences (positive means weighted is better).

## Interpretation / limitations

- This evaluates **marginal card-holder calibration**, not whether choosing a
  card using the sampler produces better game outcomes.
- The weighted method has **4 times as many proposals** as the unweighted
  one. Improvements could be due to this extra computation, not only to
  the evidence model. A later cost-matched test should compare equal proposal
  budgets and ideally include a fixed common pool with importance weights.
- Sampling proposals are generated by randomized constrained backtracking,
  which is not guaranteed to be uniform; the weighted variant is therefore
  an approximate behavioral distribution rather than a calibrated posterior.
- The evidence model assumes heuristic play with random mistakes. Testing
  against heuristic and random opponents can reveal model mismatch.
- Multiple snapshots from the same game are correlated. Treat uncertainty
  estimates at the **game level** and use held-out seeds before concluding
  one method is better.
- Do not train or tune a sampler against the same final benchmark repeatedly.

The test does not require saved model checkpoints or private external data.
